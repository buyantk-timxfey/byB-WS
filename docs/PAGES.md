# План по страницам — byBuka 2.0

> Детальная проработка каждой страницы. Идём по приоритету учётного ядра.
> Архитектура и решения — см. `CRM-PLAN.md`.

Формат каждой страницы: назначение · документы/регистры · статусы · поля · табличная часть · проведение (движения) · действия · журнал · десктоп/мобайл · что переносим из byB-WS · крайние случаи.

Порядок проработки: **Поступления → Продажи → Склад → Банк/Платежи → Финансы/P&L → Дашборд → Справочники → Транспорт → Почта**.

---

## 1. Поступления (закупка товара)

### Назначение
Фиксация закупки товара у поставщика: что, сколько, по какой цене, доставка, сроки, оплата. Это «вход» товара в систему — формирует партии для FIFO и долг перед поставщиком.

### Документы и регистры
- Документ: **Поступление** (шапка + табличная часть позиций).
- Движения при проведении:
  - `+Остаток товара` (регистр остатков) — новая **партия** на каждую позицию.
  - `+Кредиторка` поставщику (регистр взаиморасчётов) — на сумму поступления.
  - Себестоимость партии = цена закупки + **распределённая доставка** (пропорционально сумме строки).

### Статусы (3 чистых + флаг)
- **Ожидает отправки** — черновик, поставщик ещё не отгрузил. Движений нет.
- **В пути** — отгружено поставщиком. **Товар становится доступен к продаже** (оприход в остаток).
- **Завершено** — фактически доставлено и принято.
- Флаг **«Проблема»** — отдельный признак (badge), не ломает логику проведения. Ставится на любой статус (задержка, брак, спор).

### Частичный приход (важно)
Поставка может приходить частями. Поэтому **проведение — по строкам, а не разом**:
- У каждой позиции своё состояние прихода: `кол-во заказано` / `кол-во получено`.
- Движение `+Остаток` по позиции создаётся на **полученное** количество (партия = полученная часть).
- Статус шапки выводится автоматически:
  - ни одна позиция не отгружена → **Ожидает**;
  - часть/все отгружены, но не все доставлены → **В пути**;
  - все позиции доставлены → **Завершено**.
- При продаже товара «в пути» остаток уже доступен (оприход на отгруженное кол-во); недополученное доберётся следующей частью.

### Поля шапки
| Поле | Тип | Заметка |
|------|-----|---------|
| Номер | авто | Сквозная нумерация (ПОСТ-2026-0001) |
| Дата заказа | дата | `order_date` |
| ETA | дата | план. дата прихода (для трекера/календаря) |
| Поставщик | ссылка на контрагента | тип «Поставщик»/«Оба» |
| Перевозчик | ссылка | + ссылка на сайт для трекинга |
| Трек-номер | текст | `tracking` |
| Стоимость доставки | DECIMAL | распределяется в себестоимость |
| Название/комментарий | текст | `name` — отображается в трекере дашборда |
| Флаг «Проблема» | bool | badge |

### Табличная часть (позиции)
| Колонка | Заметка |
|---------|---------|
| Номенклатура | автоподстановка из справочника; можно создать новую на лету |
| Ед.изм. | из карточки товара (шт/литры/упаковки) |
| Кол-во заказано | план |
| Кол-во получено | факт (для частичного прихода) |
| Цена закупки | за единицу |
| Сумма | авто (кол-во × цена) |
| План. цена продажи | опц. (`planned_sale_price`) — для прогноза маржи |

Доставка распределяется по строкам пропорционально сумме → в карточке партии видна полная себестоимость.

### Действия
- **Провести / Распровести** (Ctrl+Enter).
- **Оплатить поставщику** — (statement-first) ведёт к быстрому сопоставлению с импортированной строкой выписки; гашение кредиторки происходит при сверке. Для редких наличных — ручная операция.
- **Вложения** — прикрепить счёт/накладную/фото (перенос `shipment_docs`).
- **Отметить «Проблема»** / снять флаг.
- Дублировать поставку (частый повтор закупки).

### Журнал (список)
- Колонки: №, дата, поставщик, название, сумма, оплачено/долг, статус, ETA, флаг.
- Фильтры: период, поставщик, статус, «есть долг», «проблема».
- Быстрый поиск по названию/трек-номеру/поставщику.
- Итоги внизу: сумма закупок, долг поставщикам за период.

### Десктоп / мобайл
- Десктоп: журнал-таблица + форма-документ с inline-таблицей позиций.
- Мобайл: карточки поставок (как трекер), форма в полноэкранном drawer; быстрые действия «оплатить», «отметить пришло».

### Что переносим из byB-WS
- Идею трекинга (ETA, кольца на дашборде), `shipment_docs` (вложения), связь с перевозчиком.
- Переделываем: статусы (3+флаг вместо ⚠️), партионную себестоимость с распределением доставки, оприход по строкам, кредиторку (новое — раньше не было).

### Крайние случаи
- **Продажа под заказ**: если продали товар до прихода — остаток в минусе, при проведении поступления минус закрывается, себестоимость проданного уточняется.
- **Изменение проведённого поступления**: распроведение → правка → перепроведение (пересчёт партий и долга).
- **Возврат поставщику** (на будущее): отдельный документ, обратные движения. В MVP — не делаем, отметить как backlog.

## 2. Продажи (реализация товара)

### Назначение
Фиксация продажи товара покупателю: что, сколько, по какой цене. «Выход» товара со склада — списывает партии по FIFO, формирует выручку, прибыль и долг покупателя.

### Документы и регистры
- Документ: **Реализация** (шапка + табличная часть позиций).
- Движения при проведении (статус «Отгружено»):
  - `−Остаток товара` (FIFO по партиям; допускается минус при продаже под заказ).
  - `+Дебиторка` покупателя (взаиморасчёты) — на сумму продажи.
  - `+Доход` (оборот, выручка).
  - `+Себестоимость продаж` (оборот) — сумма себестоимости списанных партий → даёт прибыль.

### Статусы (цикл + автоплата)
- **Жизненный цикл** (вручную):
  - **Счёт** — счёт выставлен, склад не списываем, движений нет (обязательство/КП).
  - **Отгружено** — проведено: списание склада, дебиторка, доход.
  - **Отменено** — распроведено, движений нет.
- **Индикатор оплаты** (авто, из взаиморасчётов): **Не оплачено / Частично / Оплачено**.

> Резервирование на этапе «Счёт» не делаем (продажа под заказ всё равно разрешена) — движения только при «Отгружено».

### Связь оплаты и продажи
- Раздельно: отгрузка ≠ оплата. Оплата фиксируется при **сопоставлении строки выписки** с продажей (statement-first), гасит дебиторку и признаёт выручку (кассовый метод).
- Кнопка **«Оплачено сразу»** — переход к быстрому сопоставлению (или ручная операция для редких наличных).
- **Аванс**: приход денег по выписке до отгрузки → отрицательная дебиторка (аванс), при отгрузке зачитывается.

### Поля шапки
| Поле | Тип | Заметка |
|------|-----|---------|
| Номер | авто | РЕАЛ-2026-0001 |
| Дата | дата | `sale_date` |
| Покупатель | ссылка на контрагента | тип «Покупатель»/«Оба»; можно разовый `buyer_name` |
| Счёт зачисления | ссылка | опц., для быстрой оплаты |
| Источник-поставка | ссылка | опц. «продано под эту заявку» (`source_shipment_id`) |
| Статус | enum | Счёт/Отгружено/Отменено |
| Комментарий | текст | |

### Табличная часть (позиции)
| Колонка | Заметка |
|---------|---------|
| Номенклатура | автоподстановка; показывает доступный остаток (вкл. «в пути») |
| Кол-во | продаваемое |
| Цена продажи | за единицу |
| Сумма | авто |
| Себестоимость | авто (FIFO из списанных партий) |
| Прибыль / маржа | авто (сумма − себестоимость) |

Партии списываются автоматически по FIFO (включая «в пути»); пользователь партию не выбирает.

### Действия
- **Провести (Отгрузить) / Распровести** (Ctrl+Enter).
- **Оплачено сразу** — создать платёж входящий на остаток долга.
- **Цепочка** — показать, из каких поступлений ушёл товар и прибыль по сделке (перенос идеи `chain.js`).
- Дублировать продажу.

### Журнал (список)
- Колонки: №, дата, покупатель, сумма, оплата (индикатор), прибыль/маржа, статус.
- Фильтры: период, покупатель, статус, «есть долг», только счета.
- Итоги: выручка, прибыль, средний чек, долг покупателей за период.

### Десктоп / мобайл
- Десктоп: журнал + форма с inline-позициями, живой расчёт прибыли.
- Мобайл: карточки продаж; быстрые действия «оплачено», «отгрузить».

### Что переносим из byB-WS
- `sales` + `sale_items` (шапка + позиции), `source_shipment_id`, `chain.js` (цепочка), `item_search.js` (поиск товара).
- Переделываем: статусы (цикл + автоплата вместо ручных), дебиторку (новое), себестоимость/прибыль из FIFO-партий, авансы.

### Крайние случаи
- **Продажа под заказ**: остаток уходит в минус; себестоимость уточняется при приходе партии.
- **Отмена проведённой**: распроведение возвращает партии на склад и убирает дебиторку/доход.
- **Частичная оплата / аванс**: индикатор «Частично»; аванс до отгрузки — отрицательная дебиторка.
- **Возврат от покупателя** (на будущее): отдельный документ, обратные движения. В MVP — backlog.

## 3. Склад (остатки)

### Назначение
Показать, что и сколько лежит на складе, по какой себестоимости, как давно. Это **отчёт поверх регистра остатков** + ручные складские документы (списание, инвентаризация).

### Документы и регистры
- Регистр **Товары на складе** (чтение для отчёта).
- Ручные документы:
  - **Списание** — брак/порча: `−Остаток` (FIFO), `+Расход` (убыток в P&L по статье «Списание/брак»).
  - **Инвентаризация (корректировка)** — выровнять учётный остаток под фактический: разница `+/−Остаток`; недостача → расход, излишек → прочий приход (по себестоимости).

### Вид (по товару + разворот партий)
- Строка = **товар** с суммарным остатком и стоимостью.
- Разворот строки → **партии**: поступление, дата прихода, кол-во, себестоимость единицы, дней на складе.
- Колонки товара: товар, группа, ед.изм., остаток (кол-во), стоимость (Σ кол-во × себестоимость), дней на складе (по старшей партии), флаг «залежалый».

### Аналитика
- **Замороженные деньги** — общая стоимость остатков по себестоимости (вверху страницы + по группам).
- **Залежалый товар** — подсветка партий старше N дней (N в настройках); отдельный фильтр и сумма «зависло денег».
- Топ товаров по стоимости остатка.

### Фильтры
- Группа номенклатуры, «есть остаток», «залежалые», «отрицательные» (продано под заказ, ждёт прихода).

### Действия
- **Списать** (из строки/партии) → документ Списание.
- **Инвентаризация** → документ корректировки.
- **Карточка товара** — история движений (приходы/расходы), текущие партии, оборачиваемость.

### Десктоп / мобайл
- Десктоп: таблица с разворотом партий, итоги по группам.
- Мобайл: карточки товаров с остатком и стоимостью; разворот партий по тапу.

### Что переносим из byB-WS
- Идею партионного склада (`warehouse`).
- Переделываем: остаток считается из **регистра движений** (а не хранится в поле); статусы «На складе/Частично/Продан» убираем — они выводятся из остатка; добавляем залежалость и замороженные деньги.

### Крайние случаи
- **Отрицательный остаток** (продажа под заказ) — отдельная подсветка, закрывается приходом партии.
- **Партия с нулевым остатком** — скрыта по умолчанию (доступна в истории карточки товара).
- **Инвентаризация при отрицательном остатке** — корректно поднимает до факта.

## 4. Банк / Платежи (корона)

### Назначение
Единая точка по деньгам: импорт банковской выписки, балансы счетов, **сопоставление** строк выписки с документами (сверка), разнесение по типам и статьям. Самый важный и самый сложный модуль.

### Модель денег — statement-first («как в 1С»)
- **Деньги попадают строго из выписки.** Строка выписки = движение регистра денег.
- **Баланс счёта** = начальный остаток + Σ строк выписки → всегда совпадает с банком (калибровка не нужна).
- **Бизнес-документы** (продажа/поступление/расход) дают начисления (склад, долги), но **не деньги**.
- **Кассовый метод P&L**: выручка/расход признаются при сопоставлении строки выписки с документом (совпадает с формулой «выручка = оплаченные продажи»).

### Импорт выписки
- Формат: **файл 1CClientBankExchange** (Windows-1251). API-загрузку не делаем.
- Парсер и батчи переносим из byB-WS (`bank.php`, таблицы `bank_statement_*`).
- Превью батча перед применением: период, обороты (приход/расход), нач./кон. баланс, кол-во строк.
- **Дедупликация** при повторном импорте (по № документа/сумме/дате/счёту).

### Сопоставление (сверка) — ядро страницы
- Статус строки: **не разнесена / частично / разнесена / игнор**.
- Привязка строки → документ(ы):
  | Строка | Привязка | Эффект |
  |--------|----------|--------|
  | Приход | Продажа | −Дебиторка покупателя, +Выручка (кассовый доход) |
  | Расход | Поступление | −Кредиторка поставщику |
  | Расход | Статья затрат | +Расход в P&L |
  | Приход/Расход | Перевод | Пара строк между своими счетами (вне P&L) |
  | Прочее | — | Прочий приход/расход |
- **Авто-сопоставление** по ИНН + сумме (+дата); остальное — вручную.
- Поддержка **множественной/частичной** привязки (одна строка ↔ несколько документов и наоборот) — перенос `bank_statement_matches`, `reconcile.js`.

### Категоризация (вручную + подсказки)
- Тип и статью назначает пользователь.
- Авто-правила по ИНН/назначению платежа — только **подсказывают** (можно принять одним кликом).

### Экраны
- **Счета** — карточки: баланс, сколько строк не разнесено.
- **Импорт** — загрузка файла, превью батча, применение.
- **Лента операций** — строки выписки с фильтрами и статусом разнесения.
- **Экран сверки** — слева строки, справа кандидаты-документы с авто-подбором (перенос идеи `reconcile.js`).

### Журнал / фильтры
- Счёт, период, тип, «не разнесено», контрагент, диапазон сумм.
- Итоги: приход/расход за период, неразнесённый остаток.

### Десктоп / мобайл
- Десктоп: импорт и сверка (основная работа).
- Мобайл: просмотр баланса счетов, лента операций, быстрая разметка отдельной строки.

### Что переносим из byB-WS
- Парсер выписки (`bank.php`), таблицы `bank_statement_lines/matches/batches`, движок сверки (`reconcile.js`, `bank.js`), мульти-мэтч.
- НЕ переносим: API-провайдеры банка (`_bank_providers`) — только файловый импорт.
- Переделываем: деньги = регистр из строк (а не таблица `bank_operations`), кассовый доход/расход через сопоставление.

### Крайние случаи
- **Повторный импорт** — дедуп строк, не задваивать.
- **Перевод между своими счетами** — две строки (расход на одном, приход на другом), не влияет на P&L.
- **Частичная оплата** — строка на часть суммы продажи → продажа «Частично оплачено».
- **Аванс** — приход без отгрузки → отрицательная дебиторка (аванс покупателя).
- **Возврат** — приход/расход с обратным эффектом на взаиморасчёты.
- **Эквайринг**: банк зачисляет за вычетом комиссии (~1,22%). При сверке прихода с продажей разница (в пределах допуска) авто-относится на статью «Эквайринг» (расход). Ставка/допуск — в настройках.

## 5. Финансы / P&L (корона)

### Назначение
Полная картина прибыльности бизнеса: сводка за период, динамика по месяцам, расшифровка каждой цифры до документов. Главный управленческий отчёт.

### Источник данных
Регистры оборотов (доходы/расходы) — **кассовый метод по выручке** (оплаченные продажи из сопоставленных приходов), **себестоимость по проданному** (COGS, FIFO).

### Главный экран — сводка за период
```
Выручка (оплаченные продажи)
− Себестоимость проданного (COGS, FIFO)
− Эквайринг (1,22% от продаж по эквайрингу)
− Прочие расходы ИП (по статьям)
= Валовая прибыль
Налог    = Валовая × 16%   (ставка в настройках)
Чистая   = Валовая − Налог
Зарплата = Чистая × 20%    (ставка в настройках)
```
- **Метрики**: маржа %, ROI, средний чек, число продаж.
- **График динамики 12 мес** (Chart.js).

### Вкладка «По месяцам»
Таблица: строки = статьи доходов/расходов, столбцы = месяцы. Обзор динамики и сезонности.

### Расшифровка (drill-down) — обязательно
Клик по любой цифре → список документов/строк выписки, из которых она сложилась (перенос `pnl_detail`). Из расшифровки — переход в сам документ.

### Ставки (в Настройках)
Налог 16%, ЗП 20%, эквайринг 1,22% + допуск сопоставления. Меняются без правки кода.

### Фильтры
Период (месяц/квартал/год/произвольный), счёт.

### Десктоп / мобайл
- Десктоп: сводка + таблица по месяцам + графики.
- Мобайл: карточки KPI (выручка/прибыль/маржа), свайп по месяцам, drill-down по тапу.

### Что переносим из byB-WS
- Логику `finances.php` / `finances.js`, drill-down `pnl_detail.php`.
- Переделываем: считаем из **регистров оборотов** (не из «живых» таблиц), кассовый метод по выручке, COGS по проданному, авто-эквайринг.

### Крайние случаи
- **Возвраты** — уменьшают выручку периода.
- **Продажа под заказ** — себестоимость уточняется при приходе партии → P&L пересчитывается.
- **Месяц без продаж** — корректные нули, без деления на ноль в метриках.

## 6. Дашборд

### Назначение
Сводная панель — главное за 5 секунд: прибыль, деньги, долги, поставки, задачи. «Оглавление» системы.

### Блоки (по приоритету)
1. **Прибыль / KPI** — выручка, прибыль, маржа за период + спарклайн динамики (перенос приглушённых спарклайнов из `animations.js`; волны не возвращаем).
2. **Деньги и долги** — балансы счетов, дебиторка/кредиторка (топ должников «кто кому должен»), счётчик неразнесённых строк выписки.
3. **Трекер поставок** — кольца Apple Watch по активным поставкам + календарь ETA (перенос — удачная находка byB-WS).
4. *(вторично)* **Склад/сигналы** — залежалое и замороженные деньги, просроченные ETA, отрицательные остатки.

### Заметки и напоминания (юзабельнее, чем сейчас)
- Единый блок: **быстрые заметки** с inline-добавлением (без модалок) + **напоминания**.
- **Авто-напоминания из данных** (а не только ручные):
  - продажи с долгом дольше N дней;
  - поставки «в пути» с истёкшим ETA;
  - неразнесённые строки выписки;
  - предстоящие платежи/приёмки.
- Отметка «сделано» в один тап; ручные заметки — свободные.

### Период
Глобальный фильтр периода (как сейчас) — месяц/произвольный.

### Десктоп / мобайл
- Десктоп: 6-колоночный grid (перенос макета: KPI слева, деньги/трекер справа).
- Мобайл: вертикальные карточки, KPI первыми, трекер каруселью.

### Что переносим из byB-WS
- Структуру `dashboard.php` (кольца трекера, календарь ETA), спарклайны.
- Переделываем: данные — из регистров; `notes`/`reminders` — на юзабельный единый блок с авто-напоминаниями.

### Крайние случаи
- **Пустые состояния** — подсказки «добавьте первый документ» вместо пустых блоков.
- **Нет данных за период** — KPI показывают нули корректно.

## 7. Справочники

Общий паттерн: список с поиском/фильтрами + карточка. Используются как источник автоподстановки в документах.

### 7.1 Контрагенты (полное досье)
- Поля: тип (Поставщик/Покупатель/Оба), наименование, **ИНН** (для авто-сверки), банк. реквизиты, контакты, комментарий.
- **Досье**: текущий долг (дебиторка/кредиторка) из регистра взаиморасчётов; история поставок и продаж; история оплат; кнопки перехода в документы.
- Перенос: `counterparties` + расширение полей.

### 7.2 Номенклатура (полное досье)
- Поля: наименование, **группа**, **ед.изм.** (шт/литры/упаковки), артикул, комментарий.
- **Карточка**: текущий остаток и партии; история цен закупки/продажи; оборачиваемость; прибыль по товару.
- Группы — отдельный мини-справочник (список/дерево) для фильтров и аналитики.
- Новое vs byB-WS: товар выделен из строк в справочник.

### 7.3 Перевозчики
- Поля: название, сайт (для трекинга), комментарий. Перенос `carriers` как есть.

### 7.4 Счета (деньги)
- Поля: название, начальный остаток, тип (банк/касса — оба безналичные).
- Карточка: баланс (из регистра денег), лента операций. Перенос `bank_accounts` (без API-полей).

### 7.5 Статьи затрат
- Список статей расходов для группировки в P&L (аренда, связь, топливо, эквайринг, ЗП, прочее).
- Часть статей системные (эквайринг, ЗП), остальные — пользовательские.

## 8. Настройки

- **Ставки**: налог 16%, ЗП 20%, эквайринг 1,22% + допуск сопоставления.
- **Склад**: порог «залежалости» (N дней).
- **Реквизиты компании** (для будущих печатных форм/экспорта).
- **Авто-правила сверки** (по ИНН/назначению — подсказки категоризации).
- **Аутентификация**: смена PIN, управление устройствами (Face ID/WebAuthn).
- **Бэкап БД**: ручной запуск + статус последнего (перенос `db_backup.php`).
- Параметры хранятся в БД (таблица settings), меняются без правки кода.
